# K-TransportRadar24 (`/ktransportradar24`, 옛 K-TrainRadar24 `/ktrainrader24`) — 변경 이력

> 전국 열차·항공기(·여객선·버스·지하철 순차 추가)와 강수 레이더를 한 화면에 올리는 지도.
> 열차 위치는 공표 시각표·실적 기반 추정, 항공기는 ADS-B 수신값이다. **소스는 이 저장소에 없다** — 별도 저장소
> [scoutkorea-jimmy/K-TrainRader24](https://github.com/scoutkorea-jimmy/K-TrainRader24)(비공개, 저장소 이름은 옛 이름 그대로)
> 에서 빌드해 산출물만 `ktransportradar24/` 로 복사한다. 2026-09-15(v0.9.318) 에 이름과 경로를 바꿨다.

---

## 이 서비스를 다룰 때 반드시 알아야 할 것

### 1. 여기 있는 것은 빌드 산출물이다. 여기서 고치지 마라
`ktrainrader24/` 안의 `assets/*.js`·`*.css` 는 번들이라 사람이 고칠 물건이 아니다.
고칠 것이 있으면 `K-TrainRader24` 저장소에서 고치고 `npm run build:static` 후
`web/dist/` 를 통째로 다시 복사한다. 여기서 직접 손대면 다음 복사 때 사라진다.

이 저장소의 "빌드 단계 도입 금지" 규칙과 충돌하지 않는다 — 빌드는 저쪽에서
끝나고, 이 저장소에는 완성된 정적 파일만 들어온다. 카드뉴스·디데이 React 를
해당 페이지에만 격리했던 것과 같은 방식이다.

### 2. 데이터는 미리 구워 둔 파일이다. 서버가 없다
열차 위치 계산은 전부 브라우저가 한다. 그래서 운영에 Node 서버가 필요 없고,
`api/` 아래 JSON 이 곧 데이터다.

| 파일 | 내용 | 갱신 |
|---|---|---|
| `api/index.json` | 준비된 운행일자 목록·배포 식별자 | 매 배포 |
| `api/routes.json` | 경로 형상 사전 (날짜끼리 공유) | 매 배포 |
| `api/day-YYYYMMDD.json` | 하루치 열차 목록 | 매 배포 |
| `api/rail-lines.json` | 배경 선로 형상 (OSM) | 분기 1회 |

경로 형상을 날짜마다 담지 않고 사전으로 뺀 이유는 용량이다. 30일치를 각각
담으면 같은 경부선 폴리라인을 30번 싣게 된다(약 7MB 낭비).

### 3-1. 실적(`api/history.json`)은 **매일** 갱신해야 한다
`history.json` 은 '어제·그제·3일 전'의 실제 착발 시각이다. 하루만 지나도
첫 칸이 '어제'가 아니게 된다. 주간 재빌드에 묶으면 주말에 나흘 전 기록이
표 맨 앞에 앉는다. 그래서 **일일 액션**(`.github/workflows/history.yml`)이
따로 있다.

쿼터가 다르다는 점이 이걸 가능하게 한다 — 시각표는 TAGO 공표 시각표에
기대므로 그쪽 일일 한도에 묶이지만, 실적은 한국철도공사 운행정보만 쓴다.
매일 돌려도 주간 재빌드의 한도를 갉아먹지 않는다.

손으로 돌릴 때:
```
cd ~/Desktop/VS_Code/K-TrainRader24
npm run build:history -- ../jimmyport/ktrainrader24/api
```
날짜 파일과 경로 사전은 건드리지 않는다. `index.json` 의 `historyDates` 만
고치고 `build` 는 그대로 둔다 — 그 값이 바뀌면 화면이 1MB 넘는 경로 사전을
통째로 다시 받는다.

### 3. ⏰ 약 2주 뒤에는 화면이 옛 시각표로 돈다
`api/index.json` 의 `dates` 범위를 넘기면 화면은 **가장 가까운 날**의 시각표를
띄운다(빈 화면보다 낫기 때문이다). 그 사실은 출처 배지에 `오늘치 없음` 으로
표시되지만, **눈에 잘 안 띈다.** 회귀 `regress-ktrainrader24` 가 두 가지로 잡는다.

- **'오늘 날짜가 준비돼 있다'** — 범위를 벗어났다. 재빌드·재배포 신호.
- **'오늘은 공표 시각표 기준이다'** — 날짜는 있는데 근거가 `pattern` 이다.
  TAGO 공식 시각표가 안 잡혔다는 뜻이라 시각 정확도가 떨어진다.

### 4. 이 데이터는 실시간이 아니다. 그렇게 말해서도 안 된다
어떤 API 도 **당일 지연**을 주지 않는다. 코레일 실적은 어제까지만 있고,
TAGO 는 공표 시각표(계획)일 뿐이다. 화면 하단 고지문이 그 사실을 밝힌다.
**그 문구를 지우지 마라.**

### 5. 두 API 를 쓴다. 서로의 빈 곳을 메운다
인증키는 **하나**다(공공데이터포털 계정당 하나). 활용신청이 승인된 API 는
같은 키로 전부 호출된다.

| | 잘하는 것 | 못하는 것 |
|---|---|---|
| **한국철도공사_열차운행정보** | 열차별 **중간 정차역 전부** | 계획·실적 모두 **어제까지** · 종별 없음 |
| **국토교통부_(TAGO)_열차정보** | **공표 시각표(약 2주 앞)** · 정확한 **종별** | 시·종착만 · OD 쌍으로만 조회 |

코레일에서 정차 패턴을, TAGO 에서 종별과 공식 시각을 가져와 합친다.
TAGO 는 "오늘 이 열차가 다니는가"도 알려 주므로, 안 다니는 열차가 걸러진다.

### v0.9.303 — 실데이터 전환 (코레일 + TAGO)
인증키가 들어와 시연용 표본에서 **실제 운행 데이터**로 바꿨다.

- 하루 **약 800~940편**, 종별은 TAGO 의 실제 값(KTX·KTX-산천·KTX-청룡·
  ITX-새마을·ITX-마음·무궁화 등). 번호로 추정하던 것을 전부 걷어냈다 —
  실제로 규칙이 없었다(01001 ITX-새마을 / 01007 ITX-마음 / 01151 무궁화호).
- 14일치를 미리 굽고, 그중 **12일이 공표 시각표 기준**이다. 나머지는
  TAGO 에 데이터가 아직 없는 날이라 실적 패턴만으로 만들었고 그 사실이
  `basis` 로 표시된다.
- 경로 형상을 **구간 단위로 중복 제거**했다. 인접 역쌍 9,942회 참조가
  형상 1,167개로 접힌다(88% 감소). 안 하면 routes.json 이 8.25MB 다.

**이 판에서 잡은 결함 넷** (전부 회귀에 고정)
- 동명이역이 통째로 사라졌다 — 양원역은 영동선(봉화)과 경의중앙선(서울)에
  하나씩 있는데 이름이 같다고 하나만 남겼다. 영동선 열차가 승부→양원
  3km 구간을 **249km** 로 달렸다. 이제 거리로 가르고, 어느 쪽인지는
  경로 문맥이 고른다.
- 정차역마다 따로 중앙값을 내니 **시각이 거꾸로 갔다**(47편). `승부 19:45
  출발 → 양원 19:42 도착`, 같은 역에서 `09:11 도착 / 09:09 출발`.
- 우회 가드 임계가 3배라 **영동선 18편을 잘못 걸렀다**. 태백→도계는 선로
  27.1km 에 직선 8.0km(비 3.4) — 통리재를 나선형으로 내려가는 실제 지형이다.
- TAGO 에 25편만 올라온 날을 '공식'으로 표시하고 950편을 '오늘 미운행'으로
  잘랐다. 데이터가 아직 안 올라온 것을 운행 중단으로 착각한 것이다.

**회귀 42 → 51건.** 순환 열차(홍성→서해선→천안→장항선→홍성)에서 시·종착
직선거리가 0 이라 비율 검사가 무너지는 것도 이번에 고쳤다.

### v0.9.304 — 등급 표시·지도 라벨·버전 표시 (화면만 교체)
`api/` 는 손대지 않았다. **번들만 바꿨다.**

- **열차 등급을 모양으로 나타낸다.** 근거는 한국철도공사 운전취급규정
  제55조 — 낮은 등급이 대피선으로 비켜 상위 등급을 먼저 보내는 실제 운영

  색을 못 알아봐도 급이 읽힌다. 색은 종별을 나타낸다 — 같은 급행여객이라도
  ITX-새마을과 무궁화호는 타는 사람에게 다른 열차다.
  낮은 등급을 먼저 그려 겹칠 때 상위 등급이 위로 온다.
- 아이콘이 작아 안 보인다는 지적을 받아 전국 축척 기준을 0.72배에서
  1.0 으로 올리고 어두운 윤곽을 둘렀다.
- 지도 라벨에 편명·출발지→행선지·다음 정차역. 800편에 전부 달면 못 읽으므로
  축척·겹침·개수로 억제하되, 커서를 올렸거나 선택한 열차는 항상 보여 준다.
- 상단에 앱 버전과 데이터 갱신 시각을 **나눠서** 표시한다. 주간 재빌드는
  데이터만 바꾸고 코드는 그대로다 — 한 값으로 합치면 무엇이 바뀐 건지 모른다.
- 자정을 넘겨 달리는 열차가 사라지던 것을 고쳤다. ITX-새마을 01025 는
  서울 20:09 → 부산 다음날 00:57 인데, 자정에 날짜 파일이 바뀌는 순간
  아직 달리는 이 열차가 지도에서 사라졌다.

### v0.9.323 — 여객선 뱃길을 바다로 (2026-09-16)
지미: "선박 해상 경로가 뭔가 성의가 없어보인다?" — 맞는 지적이었다. 재 보니 구간의 **42.9%**(거리 48.9%)가 두 선착장을 곧게 이은 선이었고, 가장 긴 직선이 **178 km** 라 섬과 뭍을 가로질렀다.

- **해안선으로 바닷길을 찾는다**: OSM `natural=coastline` way 31,090개를 0.004°(위도 약 444 m) 격자에 찍고 먼바다에서 물을 채워 '지날 수 있는 칸' 290만 개를 얻는다.
  저장소에는 비트로 눌러 담아 506 KB(`data/build/sea-grid.bin`, `scripts/build-sea-grid.ts`). 그 위에서 A* 로 길을 찾고 격자의 계단은 끈 당기기로 편다(`server/src/ship/sea.ts`).
- **구간마다 출처를 싣는다**(`kinds`): `osm`(실제 항로선) · `sea`(뭍을 피해 찾은 바닷길) · `straight`(둘 다 없어 곧게 이음).
  **실선은 osm 뿐**이고 나머지는 점선이다. 검증이 `straight[i] === (kinds[i] !== 'osm')` 을 강제해 추정을 실측처럼 그릴 수 없다.
  태그·상세는 `바다 위 추정 뱃길` / `일부 직선 뱃길` 로 무엇을 보고 있는지 말한다.
- **결과(09-16 빌드)**: 직선 구간 42.9% → **10.3%**(거리 48.9% → 16.4%) · OSM 항로선 57.1% · 바닷길 32.6% · 크게 돌아 버린 바닷길 22쌍 · 하루 파일 211~220 KB.
- ⚠️ **바닷길은 실제 항로가 아니다** — 수심·항만 관제·조업 구역을 모른다. 그래서 점선이고, 화면이 그렇게 말한다.
- ⚠️ 남은 직선 40개(20 km 넘는 것 14개)는 길 찾기가 아니라 **선착장 좌표 문제**다. 굽기가 바다에서 2 km 넘게 떨어진 선착장 26곳을 보고한다(제주도 15.6 km — 섬 중심점, 목포 7 km, 구도_서산시 11.1 km …). 좌표 검증은 별도로 진행 중.
- 굽기 중 길이 없는 쌍에서 A* 가 바다 전체를 뒤지다 터졌던 것(`Invalid array length`)을 상자·닫힌 칸·확장 상한으로 고쳤다. 389쌍 0.75초. 실패 시 스택을 남긴다.

### v0.9.322 — 항공기 항적 · 누르면 상세 패널 · 고르면 그것만 · 시내버스 (2026-09-16)
지미 요청: "비행기는 항적 안그려줘? 그리고 클릭하면 해당 비행기만 보여지는것도 해줘야지", "열차처럼 누르면 세부 정보 떠야지",
"모든 도시는 한국어 국문 표기법에 의거해서 도시명 작성해줘".

- **항공기 항적**: 기체를 고르면 **받은 항적(실선)** 과 **목적지까지 대권(점선 — 비행 계획 아님)** 을 긋는다.
  키 없는 원천의 항적(trace) 주소도 CORS·봇 차단이 같아, 맥미니 수집기가 15초마다 이미 받는 위치를 기체별로 모은다(30초 간격·15° 꺾이면 바로·최근 90분·120점).
  1분에 한 번 목록과 함께 올리고, 중계가 **별도 KV 키**(`ktransportradar24:aircraft-trails:v1`)에 둔다 — 목록 GET 이 항적을 매번 읽지 않게, 쓰기는 하루 1,440회 더.
  화면은 고른 기체 하나만 `GET /api/ktransportradar24-aircraft?trail=<hex>`(30초 캐시)로 받는다. 비공개(LADD·PIA)·지상·범위 밖 기체의 항적은 같은 몸통의 정리된 목록 기준으로 버린다.
  한계: 수집기가 본 구간만(수신 범위에 들어오기 전 길은 없다), 항적이 180초 넘게 낡으면 주지 않는다.
- **누르면 상세 패널 — 열차와 같은 틀**: 항공기는 분류 칩(국내·국제·통과·미상)·IATA 편명·기종·등록부호·고도·속도·진행 방위·위치 수신 나이·목적지까지 거리·

### v0.9.307 — 차량 제원·시간대 표기·글꼴 (화면만 교체 · 앱 v0.3.0)

`api/` 는 손대지 않았다. 번들과 `index.html` 만 바뀐다.

**차량 제원.** 열차를 누르면 상세에 차량 형식이 나온다. Flightradar24 가
편명을 눌렀을 때 기종을 보여주는 것과 같은 자리다. 다만 성격이 다르다 —
ADS-B 에는 기체 등록번호가 실려 오지만, **한국 공개 API 어디에도
편성번호가 없다.** 그래서 개체가 아니라 **형식**을 보여 준다. 형식은
TAGO `traingradename` 이 'KTX-산천(A-type)' 처럼 구분해 준다.

제원표만 남고 "형식 기준이라 당일 실제 투입 차량은 알 수 없다"는 단서가
빠지면, 사용자는 이 값을 그날 그 열차의 사실로 읽는다. 그 쪽이 더 위험해서
회귀가 **제원표와 단서 문장을 같이 잰다**(`차량 제원이 형식 기준임을 밝힌다`).
도감 자체는 `web/src/rollingstock.ts` 에 있다.

**시간대 표기.** 버전 줄의 데이터 시각에 `KST` 를, 시계 라벨에 `(GMT+9)` 를
붙였다. 해외에서 열면 화면의 숫자가 현지 시각인지 한국 시각인지 알 길이
없었다. 회귀 2건으로 고정했다.

**글꼴.** 본문을 원티드 산스 가변체로 바꿨다(jsDelivr `@import`).
`@import` 는 규칙보다 앞에 있어야 하므로 `style.css` 맨 위에 둔다 —
아래로 내리면 브라우저가 통째로 버린다.

**앞선 화면 묶음도 함께 나간다** (별도 번호를 붙이지 않았다):
필터 들여쓰기, 오늘 총편수 숨김(운행 중만 표시), 라벨 다중 링 배치,
UI 여백, 선택 시 다른 열차 채도·투명도 낮춤과 정차역 강조,
열차가 서지 않는 역 숨김.

### v0.9.306 — 체크박스 필터·역 표시·라벨 겹침 해결 (화면만 교체)

- **필터를 체크박스로.** 눌러서 취소선이 그어지는 방식은 "지금 켜져 있나
  꺼져 있나"를 한눈에 못 알아본다. 등급 상자는 그 급 전체를 함께 켜고 끄고,
  일부만 켜져 있으면 **중간 상태**로 보인다.
- **숫자는 지금 달리는 편수다.** 하루 총편수를 적으면 지도에 12편이 떠
  있는데 219라고 적히는 꼴이 된다. 총편수는 `/219` 로 흐리게 옆에 둔다.
  매 프레임이 아니라 1초에 한 번만 갱신한다 -- DOM 을 60fps 로 다시 그리면
  스크롤과 초점이 날아간다.
- **지도에 역을 표시한다.** 선로만 있고 역이 없으면 열차가 어디쯤인지
  지명으로만 짐작해야 했다. 역이 1,119개라 이름을 다 쓰면 못 읽으므로
  **오늘 그 역에 서는 열차 수**로 중요도를 매겨 큰 역부터 붙인다 --
  별도 등급 데이터가 필요 없고 운행이 바뀌면 저절로 따라간다.
- **라벨이 열차 아이콘을 덮던 것을 고쳤다.** 겹침 검사가 라벨끼리만 봤다.
  이제 아이콘도 자리로 잡고, 오른쪽이 막히면 왼쪽·위·아래로 여덟 자리를
  돌려 가며 놓는다. 떨어져 놓인 라벨은 가는 선으로 이어 준다.
- 초기 화면에서 제주와 남해 먼바다를 뺐다.

**회귀 64 → 68건.**

### v0.9.305 — 고지 문구·종류 필터 (화면만 교체)

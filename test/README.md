# 회귀 테스트 (krjam-planning · krjam-jebo · 랜딩 · 서비스 종료)

구조 변경 전후의 동작 동일성을 확인한다. **리팩터링 전에 baseline 을 찍고, 각 단계마다 다시 돌려 diff 가 없어야 한다.**

```bash
npm i -g puppeteer-core   # 또는 임시 폴더에 설치
node test/regress-krjam-planning.js
```

- 로컬 http 서버 + 실제 Chrome(headless). `/api/*` 는 **전부 목업** → 운영 KV 를 건드리지 않는다(§16.6).
- 커버: 부팅·탭 / 콘텐츠 보드(빈 슬롯·정렬·필터·드래그) / 캘린더 / 일정표(좌표 픽셀·취재 불필요 회색·토글·모달·전체기간) / 소식 제보→일정(날짜 분기) / 자료실(미리보기·업로드 모달·R2 13청크) / 대시보드 · 인원 / 콘솔 에러 0.
- 생성 id(`mkid()`)는 실행마다 달라지므로 비교 시 정규화:
  `diff <(grep -E "PASS|FAIL" base.txt | sed -E 's/#extra#[a-z0-9]+/#extra#ID/g') <(...)`

⚠️ 목업이라 **실제 로그인·서버 저장 경로는 검증하지 않는다.** 그 부분은 배포 후 수동 QA.

## 기사 게시판 (krjam-planning 기사 탭)

```bash
node test/regress-krjam-news.js       # 94 케이스
```
v0.9.250 에서 홍보부원 기사 탭을 아코디언 → 게시판으로 바꾼 계약을 지킨다.
- **작성 입력 순서**를 그대로 고정한다 — `제목 → 부제목 → 내용 → 사진 → 태그 → 단계`. 사용자가 직접 정한 순서라, 필드를 하나 끼워 넣다 순서가 밀리면 여기서 잡힌다.
- **단계 3종**(`draft` 초안 · `reviewed` 최종검수 완료 · `published` 퍼블리싱 완료)과 **구 `published`(boolean) 유도** — 기존 기사는 마이그레이션 쓰기 없이 읽을 때 승격된다.
- ⚠️ **부제목·태그·단계가 서버 화이트리스트(`functions/api/jp-news.js`)에 있는지도 검사한다.** 없으면 저장은 성공한 듯 보이고 값만 조용히 사라진다(데이터 소실 패턴 ①).
- **우선순위·영문·서버 알림함(v0.9.252)** — 별점 0.5 스냅과 **왼쪽 절반=.5** 클릭 · 같은 값 재클릭 시 0 · 영문 4종 화이트리스트 · 세 필드가 **버전을 올리지 않는가** · 알림 수신자 판별 · **알림 실패가 코멘트 저장을 막지 않는가** · **서버가 죽으면 화면 유도로 되돌아가는가**.
- **사진 담당자 · 장문 코멘트 · 알림(v0.9.251)** — 담당자는 이름으로 저장하고 **버전을 올리지 않는가** · 코멘트 칸이 `textarea` 이고 **Enter 로 전송되지 않는가**(전송되면 둘째 줄을 못 쓴다) · 줄바꿈이 `pre-wrap` 으로 보이는가 · 알림 대상이 **내 기사/참여 기사의 남의 코멘트**뿐인가 · 배지·모두 읽음·항목 클릭 시 모달.
- **버전(v0.9.251)** — 생성 V1 · 수정 때만 +1(단계 변경으로는 안 오름) · 히스토리에 그 판의 내용 전체 · 코멘트에 기준 버전 각인 · v 없는 옛 코멘트는 시각으로 역산 · **PUT 이 코멘트를 건드리지 않는가** · 버린 판 수를 남기는가.
- **아코디언 시절 기능이 모달에 살아 있는가** — 검수 코멘트(등록칸 포함)·카드뉴스 만들기. 화면을 갈아엎으면 부르는 곳만 없어져 조용히 사라진다(실제로 사라졌다).
- **모바일 실측** — 보이는 th 수 == 보이는 td 수(열 어긋남) · 표 가로 넘침 0 · 제목 칸 120px 이상 · 모달 바닥 버튼이 모달 밖으로 안 나감.
- **접근성 실측** — 목록·읽기 모달·작성 모달 안의 글자 13px+ / 조작 40px+, 터치 폭에서 서식 도구·코멘트 삭제 x 가 실제로 40px 인지. 화면 단위 스윕은 모달 안을 못 본다.
- 그 외 — 본문을 목록에 끼워 넣지 않는가 · 읽기 모달(본문 정화·사진·태그·단계 강조·삭제 시 닫힘) · 태그 칩 입력(Enter 커밋·중복 차단) · 다중 선택과 일괄 단계/삭제 · **일괄 삭제는 관리자만**(부원은 호출 0건).

## 서비스 종료 (`test/regress-service-ended.js`)

```bash
node test/regress-service-ended.js   # 25 케이스
```
2026-08-14(v0.9.295) 에 종료한 **카드뉴스 제작기 · 디데이 프로젝트 · 급식편의본부**를 양쪽에서 막는다.

- **덜 지우면** — 랜딩·홍보부·제보·운영현황에 종료 주소로 가는 길이 남아 참가자가 404 를 본다(실제로 6군데였다).
  주소 문자열이 아니라 **따옴표로 감싼 링크 형태**로만 잰다 — 홍보부의 콘텐츠 유형 `'dcount'`(D-count 카드뉴스 종류)는 서비스와 무관하기 때문이다.
- **더 지우면** — `jamboree/assets/logo.png`·`og-planning.png` 는 랜딩·홍보부·제보가 **아직 쓰는 공유 자산**이다.
  통째로 지우면 아이콘이 전부 사라지는데 **화면은 그대로 떠서 눈으로는 안 보인다.** 그래서 파일 존재 + 실제 렌더(`naturalWidth>0`) 둘 다 잰다.
- `_redirects` 가 **302** 인지 본다. **301 이면 브라우저가 영구 캐시**해서 되살려도 이용자가 안 돌아온다.
- 종료 안내 화면이 `?s=` 키마다 이름·설명을 갈아 끼우는지, **키가 없거나 모르는 키여도 화면이 성립**하는지.
- 디데이 안내에는 **사진·신청정보 보관 문구**가 반드시 있어야 한다(참가자 사진이 걸린 서비스다).

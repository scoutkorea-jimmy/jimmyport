# 실패 기록 (Failure Log) — 틀린 것 · 못 한 것 · 막힌 것

> **이 문서의 목적은 반성이 아니라 재발 방지다.** changelog 는 *무엇을 했는가*를 적고,
> 이 문서는 ***무엇을 틀렸고 왜 그랬는가*** 를 적는다. 잘된 일은 여기 쓰지 않는다.
>
> **작업을 마칠 때마다** 아래 셋 중 하나라도 있었으면 여기에 추가한다.
> 1. **오판·오류** — 틀린 판단을 했고 나중에 뒤집힌 것
> 2. **기술 부족** — 몰라서 못 잡았거나, 검사가 헛돌고 있던 것
> 3. **여력·권한 부족** — 하고 싶어도 **구조적으로 못 하는 것**(§3)
>
> 형식: **무엇이 / 왜 그랬나 / 어떻게 알았나 / 다음엔**. 원인이 특정 안 되면 **"특정 못 함"이라고 적는다** —
> 그럴듯한 설명을 지어내는 것이 이 문서를 망치는 가장 빠른 길이다.

## 1. 판단을 틀린 것

### F-01 · 규칙 문서를 안 읽고 "의도된 디자인"이라 세 번 넘김 (2026-08-14 · v0.9.297)
- **무엇이**: 디자인 훅이 랜딩(`index.html`)의 5건(바운스 이징 · 레이아웃 애니메이션 · 납작한 타입 계층 · 마퀴 2건)을 **세 턴 연속** 올렸다. 나는 두 번을 *"v0.9.240 에서 의도적으로 넣은 연출이므로 false positive"* 로 분류하고 넘겼다.
- **왜 그랬나**: **의도(intent)와 기준(standard)을 혼동했다.** "누군가 일부러 넣었다"를 "넣어도 되는 것"의 근거로 삼았다. 정작 이 저장소에는 판단 기준이 **문서로 있었다** — `rules/ui-ux.md`(규칙 ④, 사용자가 직접 준 가이드라인이고 *기본 동작을 오버라이드*한다)가 **3D 기교·시선 분산 오브젝트**를 금지하고, `DESIGN.md` 가 **보라/네온 그라데이션·generic AI 톤·과한 그림자**를 금지한다. 나는 그 두 문서를 **열어 보지 않고** 판단했다.
- **어떻게 알았나**: 사용자가 세 번째에 *"랜딩도 손봐줘"* 라고 했고, 그제서야 규칙 문서를 읽었다. **사용자가 안 짚었으면 계속 넘어갔을 것이다.**
- **다음엔**: **"의도된 것 같다"는 판단 근거가 될 수 없다.** false positive 로 분류하려면 그 근거를 **문서에서 인용**하거나, 문서가 없으면 사용자에게 묻는다. 특히 `rules/` 에 규칙 파일이 있는 항목은 반드시 그 파일을 열고 판단한다.

### F-02 · 잘못된 백업 검증으로 "불일치" 오진 (2026-08-14 · v0.9.295)
- **무엇이**: 로컬 파일과 라이브 응답의 SHA-256 을 비교하는데 `curl` 에 `-L` 을 안 붙여, `/index.html`·`/service-ended.html` 이 **빈 응답**을 주는 걸 해시했다. 결과 해시 `e3b0c442…`(빈 문자열의 SHA-256)를 "불일치"로 보고했다.
- **왜 그랬나**: Pages 가 `.html` 주소를 확장자 없는 주소로 **308 리다이렉트**한다는 걸 검증 스크립트에 반영하지 않았다.
- **다음엔**: 해시 비교에서 `e3b0c44298fc1c14…`(빈 문자열)가 나오면 **불일치가 아니라 "아무것도 못 받았다"** 는 뜻이다. 라이브 자산 비교는 항상 `curl -sL`.

### F-03 · Cloudflare 이메일 난독화를 배포 실패로 오진할 뻔함 (2026-08-14 · v0.9.298)
- **무엇이**: `service-ended.html` 의 라이브 해시가 로컬과 다르고, **호출할 때마다 값이 달랐다.**
- **왜 그랬나**: Cloudflare 의 **Email Address Obfuscation** 이 페이지의 메일 주소를 `/cdn-cgi/l/email-protection#<토큰>` 으로 바꿔 내보내는데, 그 토큰이 매 응답 달라진다.
- **어떻게 알았나**: 해시만 보지 않고 **`diff` 로 실제 차이를 봤다.** 해시가 다르면 무엇이 다른지 볼 것.
- **다음엔**: **메일 주소가 든 페이지는 라이브 해시가 로컬과 절대 같지 않다.** 그 페이지는 해시 대신 diff 또는 렌더 결과로 검증한다.

### F-04 · Pages 의 catch-all 을 "삭제 실패"로 오진할 뻔함 (2026-08-14 · v0.9.296)
- **무엇이**: 서비스 종료 배포 뒤 지운 자산·API 가 **404 가 아니라 랜딩 HTML 을 200 으로** 돌려줬다. 처음엔 "삭제가 안 먹었다"로 읽혔다.
- **왜 그랬나**: Cloudflare Pages 는 `404.html` 이 없으면 **못 찾은 모든 경로에 `index.html` 을 200 으로** 준다.
- **어떻게 알았나**: `/nonexistent-xyz-123` 을 같이 찔러 보고 **똑같이 200** 인 것을 확인했다 → 삭제 탓이 아니라 원래 동작.
- **다음엔**: "지운 게 안 지워졌다" 싶으면 **아무 의미 없는 주소를 먼저 찔러** 대조군을 만든다. (그리고 이 저장소에는 이제 `404.html` 이 있다.)

## 2. 검사가 헛돌고 있던 것 (기술 부족)

> ⚠️ **여기 있는 것들은 전부 "통과"로 보이고 있었다.** 이빨 확인(결함을 되돌려 넣어 FAIL 하는지 보기)이
> 없었으면 하나도 못 잡았다. **DoD 2-1 "검증 스크립트 자체를 의심한다"는 장식이 아니다.**

### F-05 · 계산된 스타일만 봐서 3D 를 못 잡았다 (2026-08-14 · v0.9.297)
- **무엇이**: 랜딩 회귀에 "3D 기울기 없음" 검사를 넣었는데, `transform:perspective(900px) rotateX(2deg)` 를 되돌려 넣어도 **통과**했다.
- **왜 그랬나**: `.reveal` 의 `animation: rise … forwards` 가 마지막 키프레임의 `transform:none` 으로 요소의 transform 을 **덮어쓴다.** 그래서 `getComputedStyle(el).transform` 이 계속 `none` 이었다.
- **다음엔**: **애니메이션이 걸린 속성은 계산값으로 검사하면 안 된다.** 스타일시트 **원문**(`cssText`)도 함께 훑는다.

### F-06 · CSS 순회가 36개 중 2개만 담고 있었다 (2026-08-14 · v0.9.297)
- **무엇이**: 위(F-05)를 고치려고 스타일시트 원문을 긁는 함수를 짰는데, **여전히 3D 를 못 잡았다.**
- **왜 그랬나**: `if (r.cssRules) 내려가기; else 담기` 로 재귀 순회를 짰다. **최신 크롬은 CSS 중첩 때문에 평범한 `CSSStyleRule` 에도 (비어 있는) `cssRules` 를 단다.** 그래서 모든 스타일 규칙이 빈 목록으로 내려가 버리고, 담긴 것은 keyframe 2개뿐이었다.
- **어떻게 알았나**: 이빨 확인이 두 번 연속 실패해서, 브라우저에서 규칙 수를 직접 세어 봤다(36개인데 함수는 3개를 반환).
- **다음엔**: `cssRules` 의 **존재**로 규칙 종류를 판별하지 않는다. 최상위 규칙의 `cssText` 에 `@media`·`@keyframes` 안쪽이 이미 다 들어 있으므로 **재귀가 애초에 필요 없다.**

### F-07 · 회귀가 실제 시계를 읽어 날짜가 지나면 통째로 빨개졌다 — **세 번 재발** (v0.9.292 → v0.9.293 → v0.9.295)
- **무엇이**: 개영식 카운트다운은 2026-08-09 12:00 이후 **숨기는 것이 정상**인데, 랜딩·제보·홍보부의 "카운트다운이 보인다" 검사가 **실제 시계**로 재고 있었다. 2026-08-14 작업을 시작하자 4개 스위트 13건이 **내 변경과 무관하게** 빨간 상태였다.
- **왜 그랬나**: 계산 함수(`state(now)`)를 순수함수로 만든 것만으로 충분하다고 봤다. **화면이 그려지는가를 보는 검사도 시각에 의존한다**는 걸 놓쳤다.
- **왜 세 번이나**: v0.9.292(`잼버리 기간 밖…`), v0.9.293(`카운트다운 3종이 초 단위로 흐른다`) 에서 각각 고쳤지만 **그때 걸린 그 검사만** 고쳤다. 같은 함정을 가진 **다른 검사들을 훑지 않았다.**
- **다음엔**: 시각에 의존하는 검사를 하나 고치면 **`new Date()`·실제 시계를 쓰는 검사를 전수로 훑는다.** 그리고 얼린 시계가 아니라 **고정 시각에서 출발해 실제 속도로 흐르는** 시계를 쓴다(그래야 "초가 흐른다"도 같이 잴 수 있다).

### F-08 · 요약을 믿고 코드를 안 봐서 1년 가까이 안 잡힘 (v0.9.287 → v0.9.293 정정)
- **무엇이**: handoff 에 *"홍보부 보드 GET 은 원래부터 `Promise.all`"* 이라고 적혀 있어 그대로 믿었다. 실제로는 **슬롯 루프만** 병렬이었고 그 아래 14개 도메인 키 + roster 는 **순차**였다. 가장 자주 열리는 화면이 KV 를 15번 줄 세워 읽고 있었다.
- **다음엔**: **문서의 요약은 근거가 아니다.** 성능·보안 판단은 항상 코드를 연다.

### F-09 · `grep` 이 큰 파일을 바이너리로 오판해 "미구현" 오진 (v0.9.231)
- **무엇이**: `jamboree-plan/app.js`(한 줄이 매우 김)를 `grep` 이 바이너리로 판정해 매치를 **조용히 0건**으로 반환했고, 멀쩡히 구현된 기능을 "미구현"으로 보고했다.
- **다음엔**: 이 저장소의 대형 JS 를 훑을 땐 **`grep -a` 를 반드시 붙인다.**

### F-10 · 파이프 뒤의 `$?` 를 보고 "전부 통과"로 오판 (DoD 2-1 의 유래)
- **무엇이**: `node test/x.js | tail` 의 종료코드는 **tail 의 것**이다. 항상 0 이라 실패가 통과로 보였다.
- **다음엔**: 출력은 파일로 받고 **실행한 명령의 종료코드**로 판정한다. "전부 통과"인데 소요 시간이 이상하면 루프가 깨진 것이다.

### F-11 · 기대값 자체가 틀렸던 것 (v0.9.286 · v0.9.293)
- **무엇이**: 조직 인원 11명을 12로 셌고, `[data-phone]` 첫 칸이 원래 빈 값인 걸 몰랐고, 8/4 20:00 이 개영식까지 **정확히 24시간**이라 `soon(<24h)` 이 false 인 걸 놓쳤다.
- **다음엔**: DoD 2-1 은 **코드뿐 아니라 기대값에도** 적용된다. 경계값을 고정 시각으로 잡을 땐 그 값이 경계에 걸리는지 먼저 계산한다.

### F-12 · 재현 안 되는 실패 2건 — **원인 특정 못 함** (2026-08-14)
- **무엇이**: (ㄱ) KV 백업 작업 중 `regress-landing` 이 **한 번** 45/46. (ㄴ) 폴더 이동 직후 `regress-service-ended` 가 **한 번** 콘솔 404 3건.
- **상태**: (ㄱ) 이후 **9회 연속** 46/46. (ㄴ) 이후 **13회 연속** 통과. **둘 다 원인 특정 못 했다.**
- **왜 못 했나**: 실패한 그 실행의 **로그를 파일로 남기지 않았고**, 크롬 콘솔 메시지에는 *어떤 주소가* 404 였는지 **들어 있지 않다**(`"Failed to load resource: … 404 ()"`).
- **조치**: 두 스위트에 `page.on('response')` 로 **4xx 응답의 URL 을 남기는 계측을 상설화**했다. 다음에 나면 로그만 보고 특정할 수 있다.
- **다음엔**: 스위트는 **항상 로그를 파일로** 받는다(`> log 2>&1`). 그리고 **플레이키를 "재현 안 되니 괜찮다"로 닫지 않는다** — 여기에 열어 둔다.

### F-13 · 몇 달 뒤 쓸 스크립트가 실패 경로를 안 다뤘다 (2026-08-14 · v0.9.298)
- **무엇이**: 연말 실행용 `scripts/purge-retired-kv.js` 가 Cloudflare API 일시 오류에 **raw stack trace 를 토하며 죽었다.**
- **왜 그랬나**: 정상 경로만 보고 "동작한다"로 끝냈다. **몇 달 뒤에 실행될 도구**라는 조건을 설계에 안 넣었다 — 그때 토큰은 만료돼 있을 수 있고, 사용자는 *지워졌는지 아닌지*조차 알 수 없다.
- **다음엔**: **나중에 실행될 도구는 실패 경로가 본문이다.** 인증 만료·API 오류·경로 없음을 전부 사람 말로 멈추게 한다.

### F-14 · 운영 현황이 **11일 낡은 검증 기록**을 이번 결과처럼 보여 주고 있었다 (2026-08-14 · v0.9.300 에서 발견)
- **무엇이**: `/admin`(운영 현황)의 검증 블록이 v0.9.295~300 내내 **2026-08-03 기록**(959건 · **이미 삭제된 급식본부 스위트 3종 포함**)을 싣고 있었다. 그 여섯 번의 배포에서 나는 매번 "2라운드 ALL GREEN"을 보고했지만, **화면에 뜬 숫자는 그 결과가 아니었다.**
- **왜 그랬나**: `scripts/gen-status.js` 는 회귀 로그 폴더를 인자로 받는데, 나는 **매번 인자 없이** 불렀다. 로그가 없으면 **조용히 직전 기록을 유지**하는 설계라 아무 신호도 없었다.
- **어떻게 알았나**: 사용자가 *"내가 더 검토해야 할 게 있냐"* 고 물어 열린 항목을 훑다가 `status.json` 의 `checksPerRound: 959` 를 봤다. **묻지 않았으면 계속 갔을 것이다.**
- **다음엔**: **조용한 폴백은 사고다.** 폴백할 때 크게 경고하도록 고쳤다. 그리고 배포 보고에 검증 수치를 쓸 땐 **`status.json` 이 그 수치와 같은지** 확인한다.

## 3. 구조적으로 못 하는 것 (여력·권한 부족)

> **이건 실수가 아니라 한계다.** 여기 있는 항목은 "다음엔 잘하자"가 아니라
> **사용자에게 넘기거나, 다른 방법으로 우회해야 하는 것**들이다. 시도하다 시간 쓰지 말 것.

| 못 하는 것 | 이유 | 우회 / 넘길 곳 |
|---|---|---|
| **운영 KV 쓰기 검증** | `SCOUT_KV` 파괴적 쓰기 금지(CLAUDE.md). 스모크 PUT 을 못 한다 | 배포되는 모듈 그 자체를 **가짜 KV(Map)** 로 돌린다. 라이브는 **GET 만** |
| **로그인이 필요한 화면의 체감 속도** | 회원/관리자 세션이 없어 실제 사용 흐름을 못 잰다 | 목업으로 동작만 확인 → 체감은 **사용자 확인 필요**로 남긴다 |
| **`git stash drop`** | 권한 분류기에 막힌다 | 사용자가 직접 실행 |
| **대화형 플러그인 설치**(`/plugin install …`) | 에이전트가 대화형 명령을 못 돌린다 | 사용자에게 명령어만 안내 |
| **MCP 서버 OAuth 인증** | 비대화형 세션에서 인증 흐름을 못 탄다 | 사용자가 claude.ai 커넥터 설정에서 승인 |
| **`puppeteer-core`** | 저장소에 없다(의존성 추가 금지 — 빌드 단계 없는 프로젝트) | 스크래치패드에 설치 후 `NODE_PATH` 로 실행 |
| **실기기 테스트** | 헤드리스 크롬만 있다. 실제 iOS/안드로이드 터치·폰트 렌더는 못 본다 | 뷰포트 에뮬레이션 + 실측(폰트 13px·터치 40px)으로 대체, 나머지는 사용자 확인 |
| **SNS 미리보기 실제 확인** | 카카오톡·페이스북 크롤러 캐시를 못 본다 | OG 주소가 바뀌면 **옛 주소를 301 로 살려** 둔다(v0.9.299) |
| **배포 전파 시점 통제** | Pages 엣지 캐시는 POP 마다 다르다 | `until` 루프로 **연속 일치**가 될 때까지 확인. **1회 확인은 근거가 아니다** |

## 4. 이 문서를 쓰는 법

1. **작업이 끝날 때마다** 위 세 절 중 해당하는 곳에 추가한다. 없으면 안 적는다(억지로 채우지 않는다).
2. 번호(`F-nn`)는 **재사용하지 않는다.** 해결돼도 지우지 말고 *"해결됨(vX.Y.Z)"* 을 덧붙인다 — **재발을 세는 것이 이 문서의 가치**다(F-07 은 세 번 났다).
3. **원인을 모르면 모른다고 적는다.** 그럴듯한 추정을 원인처럼 적지 않는다(F-12).
4. 같은 실패가 **두 번째** 나면, 고치는 것으로 끝내지 말고 **같은 함정을 가진 다른 곳을 전수로 훑는다**(F-07 의 교훈).
5. §3(구조적 한계)에 새 항목을 넣기 전에, 정말 못 하는 것인지 **한 번은 시도해 본다.** 시도 없이 "못 한다"고 적는 것도 실패다.

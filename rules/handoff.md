## ✅ 완료 정의 (Definition of Done) — 2026-07-26 사용자와 확정

> **"다 했다"고 말할 수 있는 조건.** 아래 6개를 **전부** 만족하지 못하면 완료가 아니다.
> 하나라도 못 채웠으면 보고할 때 **무엇을 왜 못 채웠는지 명시**한다(조용히 넘어가지 않는다).
> 이 기준은 사용자가 직접 정한 것이므로 에이전트가 임의로 낮추지 않는다.

1. **회귀 전체 스위트를 3회 연속 통과**한다. 관련 없어 보여도 매번 전부 돌린다.
   - `planning 137 · nav 19 · server 16 · motion 25 · press 31 · news 111 · jebo 29 · fnc(플립북) 92 · fnc보드 50 · 랜딩 38 · a11y스윕 36` = 584건 (한 바퀴 약 18분)
   - **3회 중 1회라도 실패하면 통과가 아니다.** 플레이키는 "가끔 실패"가 아니라 **결함**으로 취급한다
     (v0.9.244 실제 사례: 3회 중 2회 실패 → 장식 애니메이션이 기하 검사를 흔들고 있었다).
2. **발견한 버그는 예외 없이 회귀로 고정**한다 — 재현 → 수정 → **그 버그를 잡는 케이스 추가**가 한 세트다.
   - 눈으로 못 잡는 것(색 대비·기하·타이밍)은 **실측값**으로 검사한다. 화면을 캡처해 페이지 내 canvas 로
     디코드하는 `contrastOf()` 패턴이 그 예다(`test/regress-landing.js`).
2-1. **검증 스크립트 자체를 의심한다** — 파이프 뒤의 `$?` 는 마지막 명령의 것이다(`node ... | tail` 은 tail 의 종료코드).
   출력은 파일로 받고 **실행한 명령의 종료코드로 판정**한다. "전부 통과"인데 소요 시간이 이상하면 루프가 깨진 것이다.
2-2. **배포 시점은 1라운드**(2026-07-27 사용자 확정) — 한 바퀴 20분·3라운드 55~60분이라 화면을 그만큼 못 본다.
   **1라운드가 통과하면 즉시 배포**하고 남은 2·3라운드는 뒤에서 계속 돌리며 **5분 간격으로 진행을 보고**한다.
   검증 기준(3라운드)은 그대로다 — 앞당기는 것은 배포 시점뿐이고, 실패가 나오면 바로 고쳐 재배포한다.
   **1라운드에서 실패하면 배포하지 않는다.**
3. **배포하고 라이브를 재검증**한다 — 라이브 자산이 로컬과 **바이트 단위로 동일**한지, 전 라우트 200 인지,
   `/VERSION` 이 일치하는지. (배포 전파에 수십 초 걸린다 → `until` 루프로 기다린 뒤 확인.)
4. **문서를 갱신**한다 — 해당 `docs/<service>/changelog.md` + 이 handoff 의 최신 세션 블록.
   무엇을 바꿨는지보다 **왜 그렇게 했는지와 삽질한 교훈**을 남긴다.
5. **미완·보류 항목을 명시**한다 — 못 한 것, 일부만 한 것, 사용자 판단 대기 중인 것을 아래 '남은 일'에 적고
   보고에서도 숨기지 않는다.
6. **성능·접근성 기준을 실측으로 확인**한다 — 대비 4.5+ · 터치 타깃 40px+ · 폰트 13px+ ·
   `prefers-reduced-motion` 대응 · 콘솔 에러 0 · 요청 실패 0.

- **배정 가드** `assignBlock(pid,date,sH,eH)` = 입영 전 → 전체 오프(8/9 오후·저녁) → 개별 오프타임 순. 일정표·의전 담당 칩, 현장 배치, 촬영 상세 칩이 전부 이걸 사용. 오프타임 그리드 색: **회색 음영=입영 전(자동)** · **빨강 빗금=전체 오프(GLOBAL_OFF)** · **빨강=수동 오프(편집)** · 흰색=가능.
- **동시편집 병합**: 서버 `saveDomain` 이 `conflictByOther(baseVer,storedVer,storedAuthor,author)` 로 판정 — **다른 작성자**가 그 사이 바꿨을 때만 병합('다른 사람이 편집 중'). 같은 작성자면 통짜 저장(혼자 오탐 방지).
- **저장 flush**: 디바운스 저장(`debouncedPut`·카드·마케팅·이벤트)이 flush 레지스트리에 등록. `window.flushPendingSaves()` 가 대기분을 즉시 발사. `version-watch.js` 가 새 배포 감지 시 flush → **5초 뒤 강제 새로고침**(전 페이지 공용).
- **개영식 카운트다운**: `EVENT_DT=2026-08-05 20:00` 정밀 카운트다운(사용자가 이 방식 유지 선택; D 숫자가 20:00에 감소하는 특성 수용).

## 🖥 화면을 갈아엎을 때 (v0.9.250 교훈)
1. **옛 화면의 기능을 먼저 목록으로 적는다.** 함수와 이벤트 위임이 남아 있어도 **부르는 곳이 없으면 기능은 사라진 것**이다(검수 코멘트·카드뉴스 만들기가 그렇게 없어졌다). 회귀에 "그 기능이 아직 보이는가"를 넣는다.
2. **표는 머리(th)와 몸통(td)에 같은 클래스를 준다.** 좁은 화면에서 열을 숨기는 규칙이 td 에만 걸리면 열이 어긋나고 제목 칸이 눌린다. 회귀에서 **보이는 th 수 == 보이는 td 수**로 잰다.
3. **모달 안도 접근성 검사 대상**이다. 화면 단위 스윕은 모달을 못 본다 — 새 모달을 만들면 그 안을 따로 잰다(글자 13px+ · 조작 40px+ · 버튼이 모달 밖으로 안 나감).
